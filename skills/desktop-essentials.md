# Claude Desktop Essentials

A quick reference for what the desktop app does differently from the browser
or the CLI, and how to actually use it well.

## What the desktop app adds

- **Local file access.** Point Claude at a folder and it can read, edit, and
  save work back to your filesystem — no re-uploading files every message.
- **Skills.** Drop a `SKILL.md` folder into Claude's skills directory (or
  install one) and Claude picks up new expertise — an Excel workflow, a
  writing style, a document format — without you re-explaining it each time.
- **Connectors.** Wire up MCP servers (Slack, Google Drive, a database) so
  Claude can act on real systems, not just chat about them.
- **Projects.** Keep a running set of files and instructions scoped to one
  piece of work, instead of one long, mixed conversation.

## Getting good results

- Be specific about *where* to look — a whole Downloads folder vs. one named
  file changes how much Claude has to search before it starts working.
- Turn a repeated multi-step task into a Skill once, instead of re-typing the
  same instructions every session.
- Keep Projects scoped narrowly — one project per client, subject, or
  deliverable — so old context doesn't leak into unrelated work.
- Attach the file directly instead of pasting its contents when you can; a
  real `.xlsx` or `.pdf` gives Claude structure a pasted wall of text loses.

## When to reach for Claude Code instead

Desktop is for working with your files and knowledge day to day. Reach for
Claude Code instead when the job is really about a codebase — running tests,
multi-file refactors, or anything that benefits from a terminal and git.
